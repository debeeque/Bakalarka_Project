Разобран 14.08.2026.

- Репозиторий: https://github.com/Y6THAY/Network_Traffic_Analyzer
- Пост: LinkedIn, `yannich-thay`, активность `7491459214603898880`
- Лицензия: **MIT** (`Copyright (c) 2026 Yannich Thay`). При этом в README

  ничего не копировать дословно.

### Что это

Один файл `analyzer.py`, ~490 строк. Scapy сниффит в фоновом потоке, `rich`
рисует терминальную панель на 4 кадра в секунду: лента пакетов, топ
отправителей, телеметрия, «NIDS watchlist»; на выходе CSV и PCAP. Один коммит
в истории, демо-гифка, ASCII-баннер. Это витрина под LinkedIn, а не
эксплуатируемый инструмент.

### Дефекты, найденные при чтении кода

Записаны потому, что почти все они — готовые примеры того, «как не надо», и
часть из них прямо противоречит теории в разделе 2.3 работы.

- **IPv6 отсутствует полностью.** Единственная проверка — `packet.haslayer(IP)`,
  слов `IPv6`/`ICMPv6` в файле нет вообще. Для этой работы направление
  противоположное требуемому.
- `termios` и `tty` не импортированы, но используются в строке 442. Возникает
  `NameError`, который тут же глотается `except Exception: pass`. Cbreak-режим
  на Linux не включается никогда, выход по `q` требует ещё и Enter.
- README рекламирует «Built-in Privacy Masking (`X.X.xxx.xxx`)» — в коде
  маскировки нет ни строчки. Фича заявлена, но не написана.
- `sniff(store=0)` снабжён комментарием «to save memory», а рядом
  `all_raw_packets.append(packet)` на каждый пакет. Экономии нет.
- Фильтр по целевому IP применяется **в Python после захвата**, `filter=` у
  `sniff()` не используется. Каждый пакет тащится в userspace и разбирается,
  чтобы потом быть выброшенным. На Raspberry Pi 3 под нагрузкой это ляжет.
  Прямо противоречит разбору libpcap/BPF в теории 2.3.
- Правило детекта «порт назначения > 1024 — подозрительно» помечает весь
  нормальный ответный трафик. Это не обнаружение, а генератор шума.
- Один глобальный `threading.Lock` удерживается всё время отрисовки панели
  (4 раза в секунду) и всю запись CSV+PCAP; callback сниффера в это время
  простаивает и теряет пакеты.
- Время берётся из `datetime.now()` в момент обработки, а не из `packet.time`.
  Для файла, названного в README «forensic audit log», это некорректно.
- Проверка привилегий сделана дважды: на уровне модуля (строка 22) и в
  `check_privileges()`. Модульная делает файл неимпортируемым.

### Что перенять

1. **Набор метрик для панели.** Пакетов в секунду, средний размер пакета,
   процентная раскладка TCP/UDP/ICMP, число уникальных хостов, топ
   отправителей с полосой объёма. У нас сейчас «сниффинг + счётчик трафика» —
   это дёшево расширяется. Даёт свежий скриншот и, главное, таблицу с числами
   в раздел *Zhodnocení dosažených výsledků*. Метрики стандартные (то же самое
   в Statistics у Wireshark, в `iftop`, `ntopng`), ссылаться на репозиторий не
   нужно. **Вынесено в план на лето, пункт 9.**
2. **Экспорт `wrpcap()` кнопкой из GUI.** Одна строка кода, а на защите это
   «результат работы открывается в Wireshark». CSV-экспорт туда же — из него
   делаются таблицы в LaTeX.
3. **Резолв номера порта в имя сервиса** для читаемости вывода. Но не словарём
   на 11 портов, как у него, а через `socket.getservbyport()` — системная база
   `/etc/services`, хардкодить нечего.

### Что не брать

Всю «мини-NIDS» часть с эвристиками. Правило «порт > 1024 = угроза» на защите
разбирается за минуту. Наш разбор флагов RA по RFC 4861/4862 (`ra_audit.py`)
как «обнаружение» на порядок серьёзнее и уже описан в тексте.
